## 2026-09-27：模板宿主语音能力

- 第三方模板可按包权限声明 `speech.speak` 与 `speech.recognize`。宿主使用当前 TTS/ASR 设置和 Provider，模板不可读取密钥、录音或生成的音频文件。
- ASR 每次启动前由原生界面确认，随后申请系统麦克风权限；录音与转写状态、取消及停止由宿主控制。SDK、Mock Host 和独立语音示例已补充。
- 模板语音状态通过 `mutcube:speech` 事件通知，朗读完成返回状态，转写完成只返回文字；示例仅在用户点击保存后写入项目记录。
- 朗读进行时宿主界面自身提供“停止”入口，即使模板页面未绘制停止按钮也可终止播放；ASR 转写网络请求在用户取消时会中断。
- 宿主开发版本更新为 `0.1.3`（`versionCode=4`），用于区分 0.1.2 尚不支持的语音能力；原有 0.1.2 分发 APK 不变。
- SDK Mock Host、包校验、核心与 App 单元测试、Debug 构建通过；独立语音模板包的 WebView 桥接和录音确认取消路径在模拟器及真机使用隔离数据、语音替身通过。模拟器还验证了用户确认后文字回传。
- 真机已用真实麦克风尝试系统语音链路：系统朗读可以听到，但录音无可见音量波动，系统识别回调 `ERROR_NETWORK_TIMEOUT`（代码 1）。这不等于 Provider ASR 已验证，也不能判定超时由模板桥接引起。测试时临时授予的 Debug 应用录音权限已撤销。
- 因系统语音服务可靠性不足，模板能力现按 TTS/ASR 分别要求已配置可用的 Provider、模型及凭据；未配置返回 `SERVICE_NOT_CONFIGURED`，不弹麦克风授权、不回退系统语音。普通聊天原有的系统语音选项不受影响。`host.permissions` 保留授权列表 `granted`，新增实时可用列表 `available`。
- 真机配置小米 Provider（TTS `mimo-v2.5-tts`、ASR `mimo-v2.5-asr`）后，两轮人工朗读/录音验收：TTS 可听到，录音音量峰值均约 93%，ASR 均返回非空文字，第二轮 39 字且仪器测试通过；用户核对屏幕转写内容与所说内容完全相符。测试中未记录转写原文、音频或密钥。预设字面短语断言因与实际说话内容不一致已改为验证非空文本、真实音量波动并由说话人核对；测试临时麦克风权限已恢复为未授予。
- 为英语学习模板增加按次 ASR 语言参数 `auto` / `en` / `zh`；省略时沿用宿主全局设置，标准音频转写接口在 `auto` 时省略语言字段。模板依旧不能选 Provider、模型或读取密钥，原生录音确认会标明本次语言。SDK、示例页面、协议文档及真机桥接测试已更新；不支持的 `fr` 在录音前返回 `INVALID_REQUEST`。
- MiMo 真机英语 `language: en` 验收：TTS 完成、录音音量峰值约 94%，ASR 返回 41 字且包含英文字符，仪器测试通过；用户核对转写内容与所读句子基本一致。未记录原文/音频/密钥，测试临时麦克风权限已恢复为未授予。
