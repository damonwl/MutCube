# 代码来源与许可证策略

MutCube 自有代码以 MIT License 发布。第三方组件保留各自许可证，不因进入本仓库而改为 MIT。
允许使用 MIT、Apache-2.0、BSD 等兼容的宽松许可证组件，必须逐项核验许可证及分发义务。

## 允许作为输入的内容

- 通过正常使用软件观察到的公开行为；
- 为 MutCube 独立编写的需求、架构决策和数据格式；
- 官方平台文档；
- 完成来源登记和许可证核验的宽松许可证开源项目；
- 通过明确迁移格式导入的用户自有内容。

## 宽松许可证项目复用规则

开发新能力前应优先在 GitHub 检索成熟实现，避免重复制造通用组件。合规的宽松许可证项目可以作为依赖引入，也可以
参考、修改或复用其代码，但必须同时满足以下条件：

- 核对目标版本或具体提交的实际许可证，不能只根据仓库简介判断；
- 检查拟使用文件是否包含额外版权声明，检查其传递依赖是否使用其他协议；
- 优先作为独立依赖使用；只有确有必要时才复制源码；
- 保留原始版权声明和许可文本；Apache-2.0 组件还须保留适用的 NOTICE 并标注修改；
- 在 `THIRD_PARTY_NOTICES.md` 记录仓库地址、提交版本、使用范围和修改情况；
- 评估维护活跃度、安全风险、Android 兼容性和被项目锁定的风险。

MIT 允许复用不等于可以删除署名，也不代表该项目的所有依赖都自动变成 MIT。

## 默认禁止的内容

- 复制或机械翻译采用 AGPL 许可证的参考应用源代码；
- 未经审查复制、改写或机械翻译不兼容许可证项目的实现代码；
- 保留参考应用的包结构、内部 API、类布局、界面资产、品牌或代码注释；
- 引入来源不明确的代码。

对于不兼容许可证项目，只允许研究其公开产品行为、交互方式和设计理念。进入 MutCube 的需求说明必须用中文
重新表述，代码和测试需要依据 MutCube 自身架构独立实现，不能逐文件或逐函数对照翻译。

具体检索和引入流程见 [`OPEN_SOURCE_REUSE.md`](OPEN_SOURCE_REUSE.md)。任何例外都必须补充书面来源记录
并完成许可证兼容性审查。本文档是工程管理规则，不构成法律意见。
