# 数据备份与恢复

## 范围

手动本地备份与 WebDAV/S3 远程备份使用同一套数据快照。快照包含：

- Room 数据库：会话与消息、项目、长期记忆及压缩检查点、模板定义/绑定/记录/执行日志/摘要等。
- 白名单设置：Provider 与模型资料、显示/语音设置、MCP 配置、提示词与上下文、备份配置和提醒、Skill 安装配置。新备份不导出请求日志与扩展审计；旧备份仍可恢复这些历史条目。
- 文件：聊天附件、自定义头像、已安装 Skill 和第三方模板的包文件。

API Key、WebDAV/S3 访问密钥及 OAuth 令牌保存在独立的 Android Keystore 凭据区，不进入备份。缓存和未发送草稿也不备份。恢复到新设备后，需要重新填写凭据和授权。

应用关闭了 Android 系统自动备份。卸载应用通常会删除本机数据，因此卸载前应先创建并验证手动备份。

## 格式与安全

当前清单格式为 v3，在 v2 基础上加入已安装第三方模板文件。每份备份含实际数据库版本、创建时间、条目路径及 SHA-256 校验值。恢复前先检查路径、重复条目、解压上限、校验值及 SQLite 完整性，并在暂存数据库中运行 Room 实际结构校验和支持的迁移，不仅信任导入文件里的 identity hash。校验通过后展示项目、会话、记忆、模板记录和文件数量。仍可读取符合校验的 v1/v2 备份，包括旧版本写错数据库版本号的已知情况。

数据库备份在 Room 写事务锁内复制主文件和 WAL，再对副本执行 checkpoint；避免仅“先 checkpoint 再复制”时遗漏并发写入。附件和安装包先暂存，再计算摘要和打包，保证摘要与归档采用相同字节。备份、预览和恢复在服务内串行执行；它不是跨所有文件和设置的全局事务，操作期间仍应避免安装/卸载模板和修改大量数据。

本地备份可选择密码：留空生成普通 ZIP；输入至少 12 个字符则生成 `.mutcube` 加密文件。加密文件使用随机盐、PBKDF2-HMAC-SHA256 与 AES-256-GCM。远程新上传必须加密；旧版未加密远程备份仍可读取。备份密码只在当前操作中使用，不会保存在设备或远程服务；丢失后无法恢复加密备份。未加密 ZIP 含私人内容，请仅存放在可信位置。

## 恢复规则

恢复必须先完成内容预览与校验，再由用户确认。恢复会替换备份包含的数据库、白名单设置及文件；v1 不含的头像/Skill 数据保留本机原状。恢复前取消并等待聊天生成结束。覆盖前暂存原数据，写入失败时尝试回滚。成功恢复后应用退出，重新打开时加载新数据。若已关闭数据库后发生替换失败，即使文件回滚成功也必须重新启动；界面显示不可略过的关闭提示，避免继续使用已关闭的 Room 实例。回滚不完整会明确提示，不宣称恢复成功。

模板的历史记录仍归用户所有，但模板对数据的读取授权会撤销，需要重新授予。恢复的 Skill 一律设为停用，用户检查后可再启用。备份不覆盖本机凭据，也不会自动把旧凭据赋给恢复的 Provider。

## 验证

`TemplateBackupTest` 在隔离的临时目录中构造数据库、头像与 Skill 文件，验证预览、明文与加密备份、错误密码、文件篡改拒绝、恢复内容、模板授权撤销及 Skill 停用。不得用用户的实际应用目录进行破坏性恢复测试。
