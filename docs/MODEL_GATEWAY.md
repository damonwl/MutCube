# 模型网关

更新日期：2026-10-08。

## 当前实现

- 内置默认档案：Xiaomi MiMo API；
- 未配置时默认模型 ID 和模型列表为空，不预置 `mimo-v2.5-pro`；用户配置 Key 后发现模型或手动添加；
- 协议：OpenAI Chat Completions 兼容、Google Generative Language 与 Anthropic Messages 原生流式接口；
- 基础地址：`https://api.xiaomimimo.com/v1`；
- 网络实现：OkHttp，无请求日志拦截器；
- 流式响应：SSE `data:` 事件转换为文本、推理、工具调用增量和用量等结构化事件，供应商 JSON 不进入界面层；旧的纯文本流接口仍作为兼容视图保留。
- 请求与响应支持 OpenAI-compatible function tools、assistant `tool_calls` 和 `tool` 结果消息，参数 JSON 在网关边界解析。
- 流式请求通过 `stream_options.include_usage` 请求用量；多轮工具调用会累计各轮输入、缓存和输出 Token，
  本地同时测量总生成耗时，并与最终消息版本一同持久化。界面根据输出 Token 和耗时计算实际生成速度。
- 设置页支持多个 Provider 档案，每个档案独立保存协议、名称、HTTPS Base URL、默认模型和模型能力；可以新增、编辑、启停、排序、切换和删除（至少保留一个启用档案）。
- Provider 编辑区可使用已保存或尚未保存的 Key 请求标准 `/models` 端点，验证鉴权与连接并读取模型 ID；临时 Key 只用于该次请求，不会因测试动作写入存储。
- 模型发现按 Provider 协议适配；`/models` 是 OpenAI-compatible 的路径，不是 Google/Anthropic 共用路径。
- 全局系统提示词、上下文消息上限和图片输入开关作为生成行为单独保存，不与 Provider 身份混在一起。
- Temperature、Top P 和最大输出 Token 均可留空以使用 Provider 默认值，也可显式设置安全范围内的数值。
- 项目可以选择固定 Provider，也可以跟随全局活动 Provider；项目仍可逐字段覆盖模型 ID、生成行为和采样参数，空值表示继承。

## 流式传输与生成生命周期

- 三种协议从 OkHttp 回调向有界通道投递事件时使用背压；缓冲区满时等待消费，不丢弃文本、工具或用量增量。
- 消费端取消后退出网络读取，不在 UI 主线程阻塞投递；每种协议以 256 个增量和慢消费者进行回归验证。
- 发送、重试、重新生成和编辑重生成在 Job 已启动但界面尚未刷新时也拒绝重复排队。
- 发送前捕获目标项目/会话；流式展示、错误和清理由当前 generation attempt 标识约束，旧任务不能清理新任务的状态。
- 请求日志由 `LoggingModelGateway` 在 IO 线程写入；可选诊断失败不会把成功回复变成失败，也不会覆盖原始 Provider 错误。

上述边界的测试证据与未覆盖项见 [开源准备审查](OPEN_SOURCE_READINESS_AUDIT.md)。

## 凭据边界

每个 Provider 档案的 API Key 按档案 ID 独立存储，且只在 `core:security` 中加密保存。Android Keystore 持有不可导出的 AES-GCM 密钥，偏好存储只保存
密文和随机 IV。数据库、会话消息、运行日志和 Git 文件均不得保存明文 Key。

应用只通过 `CredentialStore` 读取凭据，并立即包装为默认脱敏的 `ApiCredential`。网络层不安装正文或请求头
日志拦截器。

## 当前生成流程

1. 用户消息先写入会话数据库；
2. 生成服务解析项目指定或全局活动 Provider，读取该档案对应凭据和当前生成设置，并仅在请求层按消息数裁剪上下文；
3. `ModelGateway` 输出文本、推理、工具调用和用量等结构化增量，文本部分由界面实时显示；
4. 模型请求工具时，生成服务只执行宿主白名单中的能力，将结果以 `tool` 消息继续交给模型，最多连续三轮；
5. 正常完成后，将工具轨迹、推理和最终文本作为同一条结构化 AI 消息写入 Room；
6. 未配置凭据或请求失败时保留用户消息并显示错误；若工具已经执行，则同时保存失败状态和工具轨迹供审计；
7. 用户切换会话或新建对话时取消当前生成，避免流式内容跨会话显示。
8. 新会话首轮回复完成后，可在后台用同一会话解析出的 Provider 生成短标题；标题请求不写入消息历史，也可在会话菜单中手动重试。

## 内置工具边界

- `current_time`：读取设备时区的当前日期时间；
- `memory_search`：检索全局及当前项目范围内的用户记忆；
- `memory_save`：仅在用户显式开启“允许 AI 写入项目记忆”时提供，拒绝疑似密码或 API Key；
- 未登记工具、错误参数和超出轮次的请求都会失败，不存在任意代码或命令执行入口。

## 扩展边界

- OpenAI-compatible、Google 和 Anthropic 分别由独立协议适配器组装请求，不假定所有服务共享同一种消息格式；
- 不提供标准模型列表端点的服务仍可手动添加模型 ID；当 `/models` 明确返回 404/405 时，连接诊断会自动退回一次最多 8 Token 的最小生成请求；
- 新协议继续通过 `ProviderProtocol` 和独立网关接入，不把供应商 JSON 暴露给聊天和界面层。

## 语音与 MCP

- ASR/TTS 协议由 Provider 和单模型能力声明，不由语音 UI 根据模型名字临时匹配。
  默认音频转写/合成接口与 MiMo 的聊天式音频请求分别适配；配置前应核对模型的语音能力。
- 普通聊天保留系统语音选项。模板的 TTS/ASR 要求分别配置可用的 Provider、模型及凭据；
  未配置返回 `SERVICE_NOT_CONFIGURED`，不回退系统服务，也不申请录音权限。
- 网络朗读采用分段合成与有界预取；完成、失败、取消和未消费的音频文件都进入清理路径。
- MCP 调用在用户批准后再次检查服务身份、端点、启停、权限和输入结构；执行上限 60 秒，取消向网络调用传播。
- 工具发现保留当前撤权状态；输入 Schema 变化后，已有允许权限重新变为询问，拒绝权限仍保留。
  模型侧工具名使用原始服务/工具身份摘要，避免短前缀、特殊字符替换和名称截断导致碰撞。
