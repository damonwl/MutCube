# 聊天中的模板能力交互

## 能力发现

项目聊天右上角菜单提供“模板能力”；空白聊天页在已授权能力存在时显示轻量入口。选择能力仅将示例请求填入输入框，不自动发送。面板按宿主实际授权过滤 CHAT 动作，工具调用总开关关闭或所选模型明确不支持工具调用时不展示可用动作。

Manifest Action 增加可选 `title`（1～80 字符）与 `example`（1～500 字符），分别用于面向用户的名称和示例请求。未声明时使用描述作为兼容回退。此元数据不扩大权限，GUI-only 动作不会因为添加展示字段而开放给聊天。

## 真实执行状态

ChatGenerationService 在实际调用前发布 RUNNING，在得到结果后发布 SUCCEEDED/FAILED，最后发布配对的 ToolResult。原生聊天渲染紧凑的执行卡片，展开后显示业务摘要或失败提示，不默认展示参数 JSON，也不展示内部推理。

执行轨迹使用既有消息 parts 持久化，重开会话可再次查看。异常或停止时未完成调用标记失败，不能留下永久运行状态。实时轨迹仅在发起调用的会话展示，切换其他会话不会看到该实时轨迹。

## 结果直达模板

TemplateDataToolService 在真实执行结果中附加宿主生成的 `presentation`：`templateId`、`actionId`、`title`、`collection`、`recordKey`、`pendingConfirmation`。仅 GENERATE 带生成记录 key；查询则进入对应集合页面。业务 `data` 保持原契约。

原生卡片校验真实 ToolCall/ToolResult 配对与哈希工具名称一致，再允许点击。跳转前再次核对当前项目的启用绑定、模板版本、CHAT 动作和集合；模板查询、确认仍经过正常运行时授权与版本检查，不存在跳转绕过权限。

宿主通过 `window.MutCubeLaunchTarget` 和 `mutcube:open-record` 事件传递目标。目标以安全 JSON 字符串编码注入，模板须等初始化读取结束后再消费，且不能自动确认。通用系统只传递定位信息，不认识健身字段。

- 健身：资料查询进入“我的”；训练记录进入日历；当前计划进入训练页；生成候选按 key 读取并打开可视化预览。
- 笔记：笔记查询定位记录区域；当前文稿定位当前内容；生成候选按 key 分页查找，展示对应文稿及确认入口。

候选卡片明确显示“尚未启用”，点击“查看并启用”仅打开详情。正式启用依旧由用户在模板中操作。当前宿主对所有内置模板统一开启可信 GUI 版本选择：健身点击“启用计划”、笔记点击“预览并确认”即为一次用户确认，不再弹第二次原生确认。关闭此宿主选项时 SELECT_VERSION 需要原生确认；外部模板不能自行开启可信选项。返回模板前的聊天不创建额外会话。
