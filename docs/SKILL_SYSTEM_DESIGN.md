# MutCube Skill 系统完整设计

状态：完整目标设计；当前仅部分实现。本文定义完整产品形态与模块契约，不代表当前代码已经具备所有能力。

当前代码已有标准 ZIP/本地草稿安装与 ZIP 导出、YAML 必填字段校验、项目作用域、自动/手动/停用策略、聊天目录与正文/文本资源按需读取、基础调用审计，以及独立管理页。尚缺远程来源及更新回滚、完整审计与开发者测试工具、受控脚本运行、备份恢复集成、模板随附 Skill、安装兼容性判定和严格的多 Skill/同名交互。聊天输入框已有可搜索的 Skill 选择器与可移除标签，但发送时仍通过 `$skill-name` 文本引用传递；后续应升级为按安装 ID 传递的结构化选择，解决同名与跨项目切换歧义。

## 1. 定位与原则

Skill 是可复用的 AI 工作流程与参考资料，不是模型工具、模板、项目记忆或长期生效的系统提示词。格式直接遵循 [Agent Skills 规范](https://agentskills.io/specification)：一个目录至少包含 `SKILL.md`，可包含 `references/`、`assets/`、`scripts/` 等文件。不发明 MutCube 专属的必填清单，也不改写第三方 Skill 内容以保存本地设置。

MutCube 负责 Skill 的安装、发现、作用域、调用、资源读取、安全执行、更新和审计。Skill 可指导 AI 如何使用宿主工具；它本身不授予工具、项目数据或模板 Action 的权限。聊天、模板 GUI 和模板后台运行可共用宿主工具，但各自只能看到当前入口被授权的能力。

四个参考产品的取舍：

| 产品 | 借鉴 | MutCube 的取舍 |
| --- | --- | --- |
| [Codex](https://developers.openai.com/zh-Hans/docs/build-skills) | 名称/描述先行，正文与资源按需加载；显式及隐式调用；目录有上下文预算 | 采用渐进加载和可见调用，不照搬其桌面文件路径与插件格式 |
| [MiMo Code](https://github.com/XiaomiMiMo/MiMo-Code/blob/main/README.md) | 名称、别名、相关性召回；高置信度自动匹配、低置信度交给模型 | 采用本地召回＋模型选择，不让检索分数直接触发有副作用的工具 |
| [Claude Code](https://code.claude.com/docs/en/skills) | 自动/仅手动调用分离；Skill 与常驻规则分离 | 调用策略属于宿主安装设置，不要求第三方修改 frontmatter；不照搬 `allowed-tools` 自动授权 |
| [Hermes Agent](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills) | 分级读取、来源与版本管理、导入前检查 | 采用可追溯来源、信任状态和资源按需读取；不默认允许 Skill 自我修改 |

## 2. 与既有概念的边界

| 概念 | 职责 | 与 Skill 的关系 |
| --- | --- | --- |
| 项目/空间 | 会话、模板绑定、模型偏好和数据授权的作用域 | 决定哪些 Skill 可见；不拥有或自动授予 Skill 权限 |
| 模板 | GUI、Action、结构化数据契约与服务运行 | 可随包推荐或附带 Skill；真正读写仍由绑定和 Action 授权决定 |
| 模型工具/MCP | 实时读取、操作与外部服务连接 | Skill 只描述何时及如何使用；工具执行时独立校验权限 |
| 用户记忆 | 经用户控制的长期事实和偏好 | 不因调用 Skill 而写入记忆，Skill 文件也不作为用户事实 |
| 快捷提示词 | 用户发送或插入的短文本 | 保持独立，不伪装成 Skill |
| 对话模式 | 持续生效的会话行为设置 | 保持独立；不能依靠 Skill 模拟常驻系统规则 |
| 知识条目 | 可检索的事实材料 | 保持独立；可被 Skill 指导检索，但不是 Skill 包 |

## 3. 标准兼容与包模型

1. 严格校验标准必填 `name`、`description`、目录名与 YAML frontmatter；保留未知可选字段，不因认识不了某厂商扩展字段就拒绝整个包。
2. `license`、`compatibility`、`metadata` 原样保留并展示。`allowed-tools` 等厂商字段只作为提示或兼容信息，绝不自动提升宿主权限。
3. 原包文件保持只读快照。启用、自动调用、项目可用范围、信任、来源、更新策略等保存为 MutCube 宿主记录，不写回 `SKILL.md`。
4. 支持内置、用户本地创建、文件/ZIP 导入、Git 仓库路径、可信目录源和未来的目录服务。远程源只用于获取版本；每次运行使用本地已校验快照，不在生成中途拉取可变内容。
5. 为每次安装分配内部 `installationId`；`name` 只是标准名称，不作为唯一数据库主键。同名 Skill 在 UI 中显示来源与作用域，显式选择不歧义；自动路由对同名冲突降级为待用户选择，不默默覆盖。
6. 安装记录包含来源 URL/仓库修订、包 hash、版本标识、许可、信任状态、兼容性、安装时间、最后检查时间和当前启用状态。若发布者未提供版本号，以内容 hash 作为不可变版本标识。

## 4. 作用域和可见性

- **全局 Skill**：用户安装后，可用于无项目会话以及获准继承全局 Skill 的项目会话。
- **项目专用 Skill**：仅指定项目的会话与该项目内被授权的 AI 工作可见。删除项目时解除关联；是否保留包文件由其安装来源决定，不擅自删除用户安装的全局包。
- **模板随附 Skill**：跟随特定模板版本安装，并仅在该模板绑定且对应项目启用时可见。解绑立即停止后续调用；已保存的调用记录仍保留版本和来源。附带 Skill 不扩大模板权限。
- **入口过滤**：普通聊天、模板 GUI 的 AI Action、后台模板运行分别构建可用 Skill 列表。Skill 依赖的模型能力或宿主工具缺失时显示“不可用及原因”，而不是让模型尝试猜工具名。
- **调用策略**：每个安装实例可设为“自动且可手动”“仅手动”“停用”；模板后台运行还须另有入口策略。默认允许阅读型 Skill 自动匹配，有明显副作用的工作流默认仅手动或执行前确认。调用策略是路由限制，真正副作用仍受工具权限约束。

## 5. 发现、匹配与上下文装配

1. 每轮开始，宿主按项目、入口、启用状态、兼容性、工具依赖和用户策略筛选目录。只装入必要的 `name`、`description`、来源短标识；目录有独立 token 预算，超限时按相关性截断并给出可搜索入口。
2. 显式调用：输入框的 Skill 选择器或文本引用形成结构化 `skillId`，而不是仅靠解析用户文本。所选 Skill 在本轮确定加载；可同时选多个，但须显示顺序和上下文预算。
3. 隐式调用：先本地按精确名称、中文别名、关键词与全文检索召回候选；再由模型在小候选集中决定是否加载。不能用“全部描述塞给模型”替代有界召回。没有工具调用能力的模型仍可通过宿主侧的显式选择或保守的单 Skill 匹配使用，不假装模型已自主选择。
4. 激活后读取完整 `SKILL.md`；`references/`、`assets/` 仅在需要时读取。读取工具只允许该包根目录内的规范化相对路径，并按内容类型、大小和总读取次数限额返回。图片等非文本资源须使用模型支持的输入类型，不能把二进制误作文本。
5. Skill 指令以低于系统规则和用户当前明确要求的层级进入本轮上下文。网页、附件、项目历史与 Skill 文件均不得冒充宿主授权。多个 Skill 冲突时先满足用户当前目标与授权规则，再提示冲突；不静默执行两套相反步骤。
6. 同一生成运行内固定包 hash；重复读取相同内容可复用。跨轮不把所有曾调用 Skill 永久注入。会话检查点只记录当前任务所需的已激活 Skill 身份及摘要；下轮若需继续，按固定版本重新读取，版本已卸载时提示而不是悄悄换成新版。

## 6. 工具、模板与数据权限

调用链固定为：`Skill 指导 → 模型提出工具调用 → 宿主按当前入口/项目/用户授权校验 → 工具执行 → 结果记录`。任何一步不能由 Skill 文本跳过。

- 模板数据继续通过声明的 Action、项目绑定、集合权限、修订检查与用户确认访问。Skill 不能直接获得 SQL、Room、WebView bridge 或模板私有文件。
- MCP、网络搜索、文件与设备能力由各自的连接和权限开关控制。Skill 声称依赖某工具，只影响兼容性提示，不自动连接账号或开放工具。
- 用户明确要求“今天改计划”时，Skill 可引导模型调用已授权的生成候选 Action；真正启用计划仍沿用模板的预览和确认流程。
- 禁止在 Skill 目录、调用日志和模型上下文中附带 API key。模型看到的工具结果遵循项目隔离和已有脱敏策略。
- 权限撤销、项目移出或模板解绑后，正在等待执行的后续工具调用必须重新校验；不能因为运行开始时曾有权限就放行。

## 7. 脚本与资产：完整目标能力

标准允许 `scripts/`，但不保证任意脚本可在 Android 上执行。MutCube 应把“标准包可导入”与“当前设备可执行”分开表达，避免宣称全兼容却静默跳过关键步骤。

- 文档型 Skill：仅阅读 `SKILL.md`、参考和静态资产，无脚本运行要求。
- 可执行 Skill：安装时解析脚本语言、依赖及预期能力，给出兼容性报告。支持的脚本通过独立的沙箱运行器执行；不支持的解释器须提供受控运行器扩展或标为不可执行，不能回退到 Android 应用进程内任意执行。
- 沙箱最小授权：每次运行独立工作目录，默认无网络、无宿主数据库、无凭据、无设备 API；用户可按任务授权具体输入文件、输出目录、网络目标与资源配额。限制 CPU、内存、时长和输出大小；取消时终止运行并清理临时资源。
- 脚本请求仍须经用户批准或明确的预授权策略。Skill 的 `allowed-tools`、脚本注释和自然语言指令均不等于执行许可。运行前展示脚本、来源、参数、输入/输出及将获得的能力。
- 脚本只产出候选文件或结果。若要写模板数据、发消息或访问外部服务，仍须经过对应宿主工具。脚本运行失败应返回可诊断错误，不伪造结果。

## 8. 安装、更新与信任

`发现 → 预览 → 校验 → 安装快照 → 设定作用域/调用策略 → 使用 → 检查更新 → 审查差异 → 原子切换或回滚 → 卸载`。

- 导入须防 ZIP Slip、路径穿越、符号链接逃逸、压缩炸弹、超大文件、重复文件名和 MIME 混淆；导入目录先复制进受控存储，再解析与建索引。格式校验可对照规范的 `skills-ref`，但宿主安全校验不能仅依赖格式验证。
- 对第三方包展示发布者、来源、许可证、文件清单、脚本与外部依赖；静态扫描提示外传数据、提示注入、破坏性命令等风险。扫描不是安全保证，危险包禁止自动调用和脚本执行。
- 本地编辑只作用于用户创建或显式 fork 的包；内置/远程包保持只读。用户修改第三方内容时生成新的本地来源，不再假装它是原发布版本。
- 更新先下载为新快照，展示 `SKILL.md`、脚本、依赖和权限变化；任何新增脚本或能力要求都需用户重新审查。切换为原子操作，失败维持旧版，保留回滚入口。正在运行的任务继续使用其固定旧版。
- 备份可保存包、安装记录与项目关联；恢复后先校验与重新确认信任和敏感授权，不自动恢复 API key、网络或脚本执行许可。卸载包不删除聊天、模板数据或调用审计；项目和模板关系按来源解除。

**创建与分发**也属于完整范围：用户可以从空白标准目录开始编写，或让 AI 根据目标、输入、输出和触发/不触发示例生成草稿；编辑器提供 Markdown/YAML 校验、资源管理、权限/兼容性检查和调用预览。AI 生成的 Skill 先保存为草稿，须经用户审阅才能启用。发布前运行正例、反例、缺参和越权测试，形成可分享的标准目录/ZIP；发布到 Git 仓库或目录服务时附许可证、版本、来源和内容 hash。目录服务只是发现和分发渠道，离线导入始终可用，不能锁定特定市场。

## 9. 产品交互

**Skill 管理页**从“上下文库”独立出来，分“已安装／发现／本地创建”三个入口。列表显示名称、用途、来源、适用项目、自动/手动状态、兼容性和更新提示。详情页可预览正文与资源树、查看工具/脚本依赖、授权、版本差异、调用记录，并提供禁用、复制为本地版、回滚和卸载。

**聊天输入区**增加不干扰日常输入的 Skill 选择入口。选中后以可删除的 Skill chip 展示；发送前可看到所选 Skill 与项目作用域。自动匹配不提前打断用户，但在回复的过程标记“已使用：某 Skill”，点击可查看触发原因、版本和实际调用的工具。仅候选但未使用的 Skill 不显示为已调用。

**项目详情**提供“可用 Skill”管理，与项目记忆和模板授权分开。模板详情显示随附 Skill 与必要依赖；绑定模板时只说明它可能如何指导 AI，不把 Skill 绑定误认为模板数据授权。

**异常反馈**区分“未匹配”“安装包损坏”“环境不兼容”“缺少工具/模型能力”“权限拒绝”“脚本失败”“远程更新失败”。每种错误给出下一步动作，不能统一显示“生成失败”。

## 10. 数据与模块落点

建议新增独立 `skill:core`（包模型、校验契约、作用域和调用事件）、`skill:runtime`（目录、匹配、加载、资源与脚本执行接口）及 `skill:ui`（管理和选择器）。Android 文件存储放不可变包快照；Room 管理安装、来源、作用域、策略、版本和运行记录。包文件不是 Room 大字段。`app` 只做依赖组装；`feature:chat` 依赖 Skill 运行接口而不解析 YAML 或读文件。

目前 `ContextLibraryStore` 的 `ContextSkill` 只是 SharedPreferences 中的名称、描述、指令和启用位，并在每轮请求中把所有启用项全文注入。目标实现要删除这条注入链，保留快捷提示词、模式、知识条目的独立逻辑。`ChatGenerationService` 改为接收本轮经过筛选的目录、明确激活的 Skill 和可用读取工具；模板引擎只获得所属项目与入口允许的 Skill。项目/记忆/模板数据模型不因 Skill 引入而迁移或改变归属。

运行记录至少包括：会话或模板运行 ID、项目 ID、安装 ID、版本 hash、显式/隐式触发、候选与选择原因、读取的资源路径、申请/实际调用的工具、授权结果、耗时和错误类型。默认不存 Skill 全文、用户私密输入或工具敏感输出；调试导出需用户主动操作并脱敏。

## 11. 验收标准

1. 标准示例包可导入、校验、启用、调用和卸载；未知可选 frontmatter 不损坏包。
2. 仅启用十个 Skill 但本轮没有匹配时，请求不注入十份正文；显式调用必定选中指定版本，隐式调用准确率有正/负样例测试。
3. 同名不同来源不会静默覆盖；项目 A、项目 B、无项目聊天和模板后台入口互不越权。
4. 禁用、解绑、权限撤销及更新切换后，后续调用立即遵从新状态；已开始运行固定旧版且每次工具执行重新鉴权。
5. `references/`、文本/图片资产可按需读取；路径穿越、超限与二进制误读被拒绝。
6. 脚本在受控运行器中成功/失败/取消均可追溯；无授权时不能联网、读密钥、读跨项目数据或绕过模板 Action。
7. 更新可看差异、需要时重新授权、失败可回滚；备份恢复不静默恢复高风险权限。
8. 用户能在聊天中看见实际使用的 Skill，开发者能复现版本与错误；调用记录不泄露密钥或原始私密数据。
9. 本地创建、AI 辅助起草、验证、导出及从已发布来源重新安装形成闭环；创建过程不会绕过用户审阅或授权。

以上是**完整目标范围**。实施时可以拆成可验证的交付批次，但不能把后续能力从目标设计中删掉，也不能将“导入了标准文件”误称为“支持所有脚本运行环境”。
