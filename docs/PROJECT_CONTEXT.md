# 项目上下文检索

日期：2026-09-17。宿主通用只读能力，位于 `core:context`，不属于健身模板或项目记忆表。

## 入口与流程

- 普通项目聊天：根据最新用户消息自动检索其他会话，把带来源的片段加入模型上下文；启用工具调用且模型未声明不支持时，提供 `project_history_search`、`project_history_read` 继续探索。
- 模板 GENERATE：按完整输入检索所属项目的会话；配置支持工具时，模型可在返回结构化结果前继续搜索、读取来源。最终输出仍接受集合 schema 校验，候选仍需用户确认；受信任内置 GUI 的可视化启用点击不再重复原生确认，AI 不会自动启用。
- 无项目的聊天不提供项目检索。工具参数不允许指定项目，项目身份由宿主装配。WebView 不增加直接读取聊天数据库的桥接接口。

搜索返回 conversationId、conversationTitle、messageId、role、createdAt（Unix 毫秒字符串）、text。展开来源返回目标前后最多两条消息。来源必须仍属于当前项目，且是未删除会话的当前可见分支；移出项目或放入回收站后拒绝访问。

## 数据边界

只取已完成的用户/AI 正文及可解析附件，不读取推理、工具调用结果或失败消息。共享 TXT/Markdown/CSV 等文本及 Office 正文提取模块，图片不额外执行 OCR。历史对话属于不可信证据，不是指令或经确认的业务记录；AI 回答和用户事实通过 role 区分，要求优先用户陈述，核对时间及冲突。

普通聊天的显式检索保存在消息工具调用记录中。模板的初始检索保存在运行快照 projectHistory，后续工具查询和结果保存在 projectHistoryTools；不修改最初的输入、配置快照或业务记录。仍遵守模板授权、运行状态和事务校验。

项目对话历史、文本记忆、模板结构化数据是不同来源。读取聊天不自动保存记忆、训练基线或训练日志，也不授予任何写入权限。相关片段会发送给该聊天/模板所配置的模型供应商；不是本地模型自动获得整个数据库。

## 首版限制

- 本地关键词匹配，长中文串拆为双字片段，不是语义向量检索；无匹配不等于用户从未提供。
- 扫描最近更新的 50 个项目会话，各取当前分支最近 100 条已加载消息；单条候选正文最多 10000 字符，每个附件使用前 6000 字符，一次最多解析 32 个附件。
- 一次搜索最多 8 条，JSON 总预算约 12000 字符；单条片段约 1100 字符，来源读取每条约 1800 字符。响应明确包含范围及截断说明。仓储目前仍按现有会话加载接口获取可见分支，尚无专用全文索引或流式长历史查询。
- 模板预检索提供每条最多 3500 字符的原始正文，优先用户陈述，证据充分时直接生成。最多 2 轮补充历史工具调用、每轮最多 2 个调用，最后一轮不再开放工具；保留整体生成超时和请求长度预算。非工具模型仍使用自动检索，不保证自动检索涵盖所有相关事实。
- 历史记录缓存相同源摘要时继续复用；失效时用有来源的本地原始摘录，不在计划生成前额外请求模型生成摘要。摘录明确标记为非 AI 摘要与可能截断，不伪造历史事实。
- 模板页显示实际准备、历史检索、缓存整理、候选生成、补充读取和校验保存阶段，不展示模拟进度百分比。模型第一段输出前仍可能有供应商侧等待；本轮不保证固定生成时长。
- 此能力改善模型证据可见性，不保证模型遵循训练轮换或重量要求；完整结构化训练基线、跨场次分部位事实读取属于模板业务的后续完善。

## 测试

`ProjectHistoryTest` 使用隔离 Room，覆盖 TXT、跨项目/回收站/失败消息/未选择分支拒绝、移出后拒绝，以及聊天与模板真实引擎的搜索/读取和运行快照。真实供应商用 `liveProvider=true` 显式启用，只读取已有配置和凭据，不写用户项目或训练事实。
