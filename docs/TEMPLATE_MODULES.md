# 通用模板系统：模块与集成边界

更新日期：2026-10-08。当前支持随 APK 发布的内置训练模板，以及通过本地包导入的第三方模板。
第三方来源尚无开发者签名认证，不能视为可信代码；安装、绑定和每次调用均受宿主校验与授权约束。
旧模板协议和业务包已经移除，不提供兼容入口。

第三方开发请从 [包规范](TEMPLATE_PACKAGE_V1.md)、[SDK](../template-sdk/README.md) 和
[QUICKSTART](../template-sdk/QUICKSTART.md) 开始。完整文档入口见 [文档导航](README.md)。

## 概念

- 宿主：拥有用户数据库、模型网关、密钥及权限检查，提供受控的数据操作工具。
- 模板服务：声明集合、数据策略、Action 和 GUI，不拥有数据库或模型凭据。可以类比 SaaS 的服务定义。
- 项目实例：项目 + 模板 ID 唯一定位的服务使用实例，可以类比服务的租户；所有操作的项目身份由宿主提供。
- GUI / 项目聊天：同一服务的两种入口，统一调用 Action 引擎。聊天不能提交任意集合名或数据库操作。
- Action：具有输入契约、执行类型、目标集合及 GUI/CHAT 暴露声明的操作。
- 集合：业务结构由模板声明；宿主持久化，数据归用户。可修改集合、只追加历史和版本候选分别治理。
- AI 运行：独立运行记录，保存输入、结果、状态、脱敏错误、模型参数和上下文快照，不创建普通会话。
- 候选与当前版本：AI 生成候选；用户确认后以乐观锁切换指针，历史版本保留。受信任内置 GUI 使用宿主允许的单次可视化确认；其他页面默认原生确认，删除始终原生确认。

## 模块

| 模块 | 职责 |
| --- | --- |
| template:core | 协议 2、声明校验、JSON 契约、实例身份、统一 Action 引擎与宿主端口；不依赖业务、Room、UI 或模型 SDK |
| template:runtime | MutCube 宿主适配、受控 CRUD、AI 执行、上下文及摘要 |
| core:context | 宿主通用项目对话检索、来源展开、共享附件正文提取；聊天和模板运行复用 |
| template:builtin | 训练记录的服务声明；智能笔记仅保留为开发与测试样例，不向用户注册。业务字段不进入宿主引擎 |
| template:ui | 安全 WebView、主题、退出处理、原生删除/版本确认、运行记录 |
| App | 注册内置服务、装配资源、项目入口、按声明生成聊天工具 |
| template-sdk | 浏览器桥接、TypeScript 类型、Mock Host；源码随仓库维护，不发布 npm |
| core:database | 用户持久层、集合契约、授权、审计、事务及修订检查 |

## 当前实现

内置与第三方模板共用协议 2 和 Action 引擎；模板包封装使用 Package v1。
本地安装支持检查资源 Hash、展示权限、升级及保留/删除数据的卸载流程；Hash 不等于来源认证。
SDK 可调用声明且授权的宿主能力，包括配置后的 Provider TTS/ASR；不可读取 Room、任意私有文件、Key 或原始音频。

两种入口只提交公开输入，由宿主注入声明的上下文，再通过同一引擎校验并执行；没有完整输入的 GUI 绕过路径。启用时按已声明 Action 和上下文绑定计算必要的集合权限，不自动给所有集合授予全部操作。聊天只获得声明 CHAT 的查询/生成 Action；写历史、直接改记录、删除和确认版本不开放给模型。权限撤销后立即从工具列表移除，再次调用仍检查权限。

CRUD 仅适用于 MUTABLE 集合；UPDATE/DELETE 检查目标记录修订，DELETE 还需原生确认。历史集合不能覆盖或删除。AI 候选源版本在生成前、写入前及原生确认后再次校验。

`mutcube.notes` 2.0.0 的源码仍作为开发与测试样例保留，但不再注册到 App 的模板列表。已有笔记数据不随此次界面调整删除。

`mutcube.fitness` 2.1.0 按新协议实现基本资料、训练草稿、实际记录、日历及 AI 计划候选。业务集合与操作均由模板声明，宿主没有健身专用字段或执行分支；设计见 FITNESS_SERVICE_V2.md。每个项目只启用一个模板，旧多绑定需重新确认；改绑撤销权限但保留数据。聊天与模板使用宿主只读项目历史检索，边界见 PROJECT_CONTEXT.md。旧健身与旧验证实现及数据不恢复。

## 数据重置

Room 17→18 升级一次性清空 8 张模板表：集合、绑定、权限、记录、运行、审计、摘要及当前版本指针。运行字段改为 actionId。项目、会话、消息、记忆、Provider 及加密凭据不清理；不采用卸载或全库破坏性迁移。重新启用新模板需要授权。

删除的数据库记录没有本次自动备份；代码可以通过 Git 历史找回。已有旧备份恢复时，升级仍清除旧模板数据，不重新激活旧服务。设计原型和旧进度文档仅作为历史设计材料保留，不构成兼容实现。

## 明确边界

仍未开放第三方安装、签名、市场、完整开发者 SDK、多实例、逐 Action 独立持久化授权、独立 Proposal 表、通用聊天确认写入或软删除。当前删除可修改笔记为真实删除，经过确认；不能描述为回收站或完整审计事件溯源。AI 辅助整理之外的确定性数据逻辑仍由程序负责。
